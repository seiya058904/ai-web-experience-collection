# ATLAS — Scene Architecture

## One geographic frame

锚点始终是 **35.4875° N / 138.8079° E**。地区数据使用 Web Mercator 对齐，渲染采用以该点海平面为原点的东／上／南坐标：X 向东、Y 向上、Z 向南，单位为千米。整部作品共用镜头与绝对滚动进度；章节名是观察尺度的标记。

一条赭红色重点线连接不同表达：它先强调真实等高线，再将注意力传递给真实水系、道路路线和球面标记。等高线与水线之间的中间形状是作者设计的几何插值；端点来自实际数据，中间形状不代表新发现的河道。线的图形身份连续，地理语义会明确改变。

坐标点的位置不随构图需要移动。低位镜头使它离开视野时，界面显示带方向的 `OUTSIDE FRAME` 标记；这与投影在地形上的点有明确区别。球面坐标由原经纬度计算，地球中心为 `(0, -6371, 0)`，原点与半径 6371 km 的球面相切。

## Constructed systems

| 观察阶段 | 专门构建的视觉系统 | 连接到下一尺度的方式 |
| --- | --- | --- |
| Coordinate | 固定地理点、十字线、刻度、坐标排版 | 线条从坐标延展为网格 |
| Grid | 地理投影规则、比例与程序化形变 | 网格过渡为从真实 DEM 提取的等高线 |
| Contour | 与当前地形三角网格配对的 100 m 等高线、500 m 主等高线、稀疏高度标签 | 原等高线顶点逐步获得 Y 向高度 |
| Relief | 同一 DEM 网格、法线、坡面着色和移动光源 | 保留等高线与地形的配准关系，显露真实山谷 |
| Water | 真实水面／水线几何与路径强调 | 视觉关注转向湖泊、涌泉和地图中的河道 |
| Satellite / Aerial | 与地形同坐标的影像 shader、世界空间材质前沿 | Landsat 色彩贴覆原网格，真实城市航拍在正确范围内细化 |
| City | 真正的道路和建筑轮廓、共同注册的细节地面、合并后的体量几何 | 先读到平面轮廓，再从同一轮廓升起 8 m 示意体量 |
| Route | 现有道路图上的连续路线、独立细线核心与光晕、沿地面三角形细分的线带 | 镜头沿真实中心线前进，降到相对观察点约百米量级的低位斜视 |
| Time | 同一场景中的太阳方向、金色过渡、坡面着色和示意窗口光 | 日间经金色时刻进入夜色，地理数据保持同一快照 |
| Orbit | 对数尺度镜头、区域恢复、平面到球面的曲率变化 | 同一坐标下城市变小，区域和地球轮廓接管观看尺度 |
| Atlas | Natural Earth 陆地遮罩与海岸线、日本周边距离场、经纬网、薄大气 | 开场的坐标以地球上的一点结束 |

## Registered terrain and city

区域地面采用桌面 **513 × 513**／手机 **257 × 257** 节点。每个单元固定使用 `[a,c,b]`、`[b,c,d]` 两个三角形，分别加载从该网格精确求交生成的 `contours-100m.json` 或 `contours-mobile.json`。三角形内的全部折点保留，抬升时线与地面使用同一高度系数。线条另有 12 m 的显示偏移以避免深度闪烁；这不是等高线标注值，也不写入源数据。重点线和区域水线另有各自的可读性偏移。

城市地面采用桌面 **257 × 257**／手机 **129 × 129** 节点。`registeredDetail()` 将细节范围外缘 5% 的高程逐渐接回区域地面；城市地面、建筑基底、道路、路线和镜头观察点共同使用该注册结果。道路与路线中心线在网格横边、纵边和对角线的交点处分段，再按实际三角面采样，而不是只在原始道路端点读取高度。地面与线带之间的亚米级显示偏移用于深度分离。

城市体量来自真实平面轮廓，统一升起 8 m；道路的轻微加强和水边线的降低是图层层级设计。路线没有把开场坐标拉到道路上；镜头跟随现有中心线，坐标保持固定。低位镜头是示意城市中的空间观察，并非行人眼高或街景摄影。

## Scroll lifecycle

相机和材质直接根据归一化文档滚动进度 `p` 求值。单一 Lenis 实例平滑滚轮输入（`lerp: 0.105`、`syncTouch: false`、`autoRaf: false`），由现有 RAF 先推进滚动，再更新镜头、地形、城市、界面与地球。资源等待期间同一 RAF 仍推进 Lenis；环境时间单独累计，用于缓慢光照和路线细节。目录导航通过 Lenis，恢复和重排使用立即定位。减弱动态关闭滚轮平滑；触摸和对话框内部保留原生滚动。没有新增 RAF、GSAP ticker 或 CSS 平滑滚动。

页面将 `history.scrollRestoration` 设为 `manual`，在首次资源等待前读取刷新／历史返回所保存的进度；普通打开可使用章节 hash。之后的数据加载不会再覆盖用户已经输入的滚动位置。页面隐藏或离开时暂停 RAF 并记录进度，`pageshow`／重新可见时取消旧请求并恢复唯一循环。较大的窗口尺寸变化按之前的归一化进度调整文档位置。减少动态效果保留直接姿态，停止环境时间推进，并只在画面状态变化时重绘。

稳定停留时的可读地图、轻微光照变化与后续尺度操作共用同一套几何。各系统的可见性和材质权重可以重叠，不要求一章卸载后下一章才出现。

## Resource lifecycle

以下进度是预加载门槛，不是画面的硬切章节边界。

| 时机 | 资源行为 |
| --- | --- |
| 初始化 | 读取区域 DEM、匹配等高线、区域水路矢量，以及供路线镜头使用的城市高程与路线 CPU 数据；建立基础地形和线条 |
| `p > 0.30` | 预加载区域 Landsat 纹理 |
| `p > 0.48` | 预加载城市精细高程、航拍纹理及地面网格 |
| `p > 0.51` | 加载城市模块和真实城市矢量，构建合并建筑、道路、水系及路线几何 |
| `p > 0.81` | 加载地球模块与 Natural Earth 陆地，生成球面所需遮罩和几何 |
| `p > 0.977` 且地球就绪 | 移除并释放城市几何／材质、城市精细地面／航拍与区域卫星 GPU 纹理；保留基础地形和共享地理数据 |
| 反向回到相关门槛 | 从随附本地文件重新预加载纹理并重建细节 GPU 资源；已解析 JSON 与 Float32 网格通过共享 Promise 缓存复用 |

区域与城市精细资源只在进度小于 `0.967` 时启动新预加载，避免在结尾反复加载和释放。几何图层没有自己的 RAF，也不持有镜头或渲染器。实现位置见 [`src/main.ts`](../../experiences/atlas/src/main.ts)、[`src/geo.ts`](../../experiences/atlas/src/geo.ts) 和 [`src/world/terrain.ts`](../../experiences/atlas/src/world/terrain.ts)。

## Responsive composition and pixel budget

首次加载根据视口宽度选择数据 LOD：手机使用 257 节点区域网格、其匹配等高线、129 节点城市网格、1024 纹理和 2400 个建筑轮廓；桌面对应 513、257、2048 和 6500。调整窗口会改变镜头、坐标标签布局与画布，当前页面保留最初选定的数据配对。

手机卫星镜头将目标向西移动以保留富士山与城市的关系，低位路线使用更紧凑的横向文字留空；最后的球面镜头扩大视野并下移构图。标签遵守画面边缘、文字区域和彼此间距的避让条件。

WebGL DPR 取设备 DPR、桌面 1.5／手机 1.6、`3200 / width`、`1900 / height` 中的最小值，再设 0.6 的下限。约 3200 × 1900 是渲染目标预算；**4K 指大视口构图适配，不是原生 4K WebGL 背缓冲的承诺**。窗口布局分辨率与地理数据精度也是不同概念。

## Cartographic globe

地球使用同一份 Natural Earth **1:50,000,000** 陆地多边形生成 4096 × 2048 全球陆地遮罩，并绘制真实海岸线与 15° 经纬网。日本周边 **120–148° E / 24–49° N** 另生成一个 2048 × 2048 有符号距离场：距离直接来自同一多边形的真实线段，用于中等高度观察时的边缘抗锯齿，没有额外数据请求。镜头高度增加时，其权重逐渐退回全球遮罩。见 [`src/world/globe.ts`](../../experiences/atlas/src/world/globe.ts)。

球面保持矿物蓝海洋、灰绿陆地和克制的大气边缘；光照由作者设定。它是制图表达，不是全球高清摄影、全球 DEM 或天文模拟。更大的遮罩与更清晰的边缘不会补出 Natural Earth 未记录的海岸细节。

## Data honesty

GSI 地形、照片、道路和建筑轮廓具有实际来源。区域 DEM 下载样本的当地间距约为 31 m，城市下载样本约为 8 m；显示网格由这些输入重采样。GSI RGB 高程的厘米编码增量、等高线求交的微小数值误差和渲染纹理的像素数均不等于测量精度。Natural Earth 的 `50m` 是比例尺系列名称，**不是 50 米空间分辨率**。

影像保存源数据的季节、积雪和地表色彩，渲染时的材质与光照由作者处理；区域 Landsat 拼接与城市航拍是不同的多日期产品。地形展开、显示偏移、地形接边、8 m 建筑体量、窗口图案、路线运动与日间／金色时刻／夜色变化都是表现方式，不代表新的地理测量、真实建筑立面、某个时刻的太阳位置或实测夜间灯光。没有 AI 生成地理运行资源。

完整许可、附加署名、原始输入与处理限制分别见 [`ATTRIBUTION.md`](../../public/atlas/ATTRIBUTION.md)、[`PROVENANCE.json`](../../provenance/atlas/PROVENANCE.json) 和 `data-source/` 中的两份说明。
