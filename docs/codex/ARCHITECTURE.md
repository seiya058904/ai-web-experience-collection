# 运行架构与维护约束 / Architecture

本文依据 [DESIGN.md](DESIGN.md) 和完成的源文件记录实现职责与维护约束。具体浏览器验证结果与限制见 [QA.md](QA.md)。

## 1. 一条进度轴，一个场景世界

页面采用原生 JavaScript、Three.js、Lenis 和 Vite。实际滚动位置被映射为连续章节进度；每幕包括进入、稳定构图、响应停留、交接和退出。

Lenis 负责唯一的平滑滚动行为。页面统一的 `requestAnimationFrame` 推进滚动和可见视觉状态，避免另起一个平滑滚动系统与浏览器输入竞争。程序化模型从绝对进度重建姿态：前进、后退或目录跳转都应落在同一个几何状态，不能依赖此前已经播放了多少次动画。

过场中的视觉变化可以有局部 easing，但不应累积改变纸帖数量、缝线连接或封面铰链位置。

## 2. 渲染职责

| 层 | 职责 | 维护原则 |
| --- | --- | --- |
| DOM / CSS | 标题、正文、目录、章节跳转、动态效果控制、终幕按钮 | 文字保持可选择、可访问；可操作元素使用真实控件 |
| 首幕书体图像 | 选定生成素材的材质基准与完整对象序章 | 保持比例、纸边和接触关系，平稳交接至几何场景 |
| Three.js | 纸张、书帖、缝订、书脊、环衬、封板、包覆、字印和终幕书体 | 各幕共享同一对象逻辑，遮挡与铰链关系明确 |
| Canvas | 受控的梳理／位移纹样 | 固定源纹样与种子；转移后环衬纹样随纸面固定 |
| 本地字体与纹理 | 字体形态、书布、marbling 和物体标题表面 | 通过项目资源路径载入，不依赖生产 CDN 或生成 API |

程序化几何属于源码的一部分；项目没有另行导入第三方模型。Visual Bible 的十张完整网页关键帧用于对比画面目标，不承担运行时界面交互。

独立 GLB 将完成态材质转为标准 PBR，并内嵌纹理与几何；它不保存实时折叠、穿线或压印的程序逻辑。需要修改交互时应维护 `src/book.js` 和 `src/model/paper.js`，而不是替换为静态 GLB。导出边界见 [模型说明](../../provenance/codex/models/README.md)。

## 3. 物体关系

**纸张与折轴。** 一张纸包含可读厚度、细小纤维变化和柔性弯曲。折线成为书帖中心，多个折帖在一致的背面轴上排列。纸页不能在折叠时穿过邻页或把折轴移到自由边。

**缝线与承托。** 缝线沿折背站点进出，承托带横跨书脊。暴露在外的段落、进入纸帖的段落与收紧动作共同体现结构连接。生成图中的简化线迹只是视觉参考。

**书芯与书壳。** 衬层整理书芯背面；封板有自己的厚度与活动区域。书布包边折向封板内侧，环衬与内封面形成关系。终幕开合使用铰链与纸块形变，不把整本书当成两个独立盒子。

**纹样与字印。** 浴面运动在转移后结束，环衬沿用同一纹样。封面字属于物体材质和空间表面，跟随封面位置、光线和遮挡。页面标题仍是独立 DOM 文字。

工艺依据和有意简化见 [CRAFT-SOURCES.md](CRAFT-SOURCES.md)。

## 4. 资源与运行约束

资产由 `public/` 提供。正式构建输出到 `dist/`，其中包含页面所需的字体和图像。浏览器查看与重新构建不需要 imagegen 凭证；生成已在制作阶段完成。

性能控制以可读画面为优先：限制纸页数、几何细分、纹理尺寸、Canvas DPR 和同时活动的场景。隐藏页面时暂停不必要渲染；离屏视觉不持续承担完整更新成本。移动端调整对象与文字的布局，保留缝订、marbling 和包覆这些关键过程。

Three.js 的有效 DPR 上限为桌面 1.65、窄屏 1.35；marbling 为桌面 1.5、窄屏 1.25。两块显示画布各自还受 4,194,304 像素的总量限制，尺寸向下取整。大屏可以使用低于 1 的有效 DPR，DOM 文字仍保持原生分辨率。Marbling 的两个材质空间缓冲区另行限制为最长边 1536 像素，窄屏 1024 像素。

低于 650 像素高的横屏缩小书体并将终幕操作排为一行；低于 700 像素高的窄屏在打开封面时进一步缩小并下移物体，保留操作区。MARBLE 以随场景渐隐的遮罩保护标题和固定控件的对比度。

以下为维护时应保留的行为约束：

- 窄屏时文字与书体不相互遮挡，目录可以触控和键盘操作。
- 系统减少动态效果设置与页面控制可停止或减轻持续运动。
- 目录打开时焦点与关闭行为清楚，关闭后返回合理位置。
- 连续快滚、反向滚动、拖动滚动条、跳转章节和重新观看都可恢复一致状态。
- 纹样冻结后不滑离环衬；封面标题不脱离封面。
- 资源使用可移植路径，并在生产构建和项目子路径下实际检查。
- 渲染失败与资源加载失败的行为需记录；不能以未观察到错误代替兼容性验证。

## 5. 本地构建边界

`npm run dev` 用于开发，`npm run build` 生成静态产物，`npm run preview` 查看最终构建；也可用 Python 标准库服务器读取 `dist/`。具体命令见 [README.md](../../README.md)。

项目交付不包含服务端、数据库、账号系统、支付、遥测或运行时内容接口。所有任务限定为本地开发、预览、构建与 QA。

## 6. 当前验证状态

1536 × 1024 桌面与 390 × 844 手机纵向的十幕停留画面、目录、章节控制、开合、重新观看、动态效果偏好及反向状态已检查。生产构建在本地相对子路径下通过资源与交互检查，强制 WebGL 不可用时的静态回退也已检查。

360 × 640 和 844 × 390 的定点视觉复查，以及 4K 实际绘图缓冲尺寸核对也已完成。最终源码不含用于画面采样的临时全局调试入口。实际结果、截图超时边界和未覆盖环境统一记录在 [QA.md](QA.md)；交付文件的 SHA-256 见根目录清单。
