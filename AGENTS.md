## Adding a supplied website ZIP

Follow this sequence for each new independent work. Keep each work's established identity, content, controls, motion and accessibility behavior; integrate its existing source rather than rebuilding it.

1. **Inventory the delivery before extraction.** Record the ZIP's byte length, SHA-256, entry count and modification time. List entries, check for a single expected top-level directory, path traversal/absolute paths, nested archives, generated duplicates, lockfiles, startup scripts, and supplied source, asset, attribution and license records. Extract only to a fresh temporary directory outside the repository, then audit the extracted source and package/license claims. Keep the original ZIP outside the repository; never commit or deploy it.
2. **Choose the smallest import boundary.** Put runtime source in `experiences/<route>/`, the page in `pages/<route>/`, namespaced runtime assets/fonts/licenses in `public/<route>/`, and design/source/provenance records in `docs/<route>/` and `provenance/<route>/`. Preserve byte-sensitive assets and upstream licenses. Do not copy an upstream `dist/`, `node_modules/`, standalone package manifest/lockfile, or independent build/server configuration into the collection. Reuse the root lockfile and installed dependency versions; dependency changes require separate task authorization.
3. **Integrate navigation and runtime boundaries.** Register the page input and sitemap URL in `vite.config.ts`; add its route, page title, canonical/social identity and required output/license assertions in `scripts/verify-build.mjs`. Use one independent HTML document and runtime per work, base-aware asset/cross-work links, the shared Collection return control, and its own lifecycle/clock. The Collection home must remain useful without JavaScript and must not import work runtimes.
4. **Update all collection records together.** Add one native-link gallery entrance using media from the supplied work or a capture of its actual runtime; retain the restrained gallery frame and the work's own typography/color. Update homepage descriptions and social alt text, About & credits and license links, `README.md`, `PRODUCT.md`, this guide, the Collection design contract, `ATTRIBUTION.md`, sitemap/build identity checks and any relevant work docs. Keep the work's independent name and describe illustrative values honestly.
5. **Keep provenance reviewable.** Add the source ZIP hash and per-entry path/size/SHA-256 to `provenance/deliveries/import-manifest.json`; preserve supplied prompts, sources, font records and license texts in their scoped provenance/public locations. Record any omitted compiled duplicates or local tooling and verify imported asset hashes. Do not delete uncertain original files.
6. **Verify before Git/release closeout.** Run focused work checks plus `npm test`, `npm run build`, `npm run verify:build`, and `git diff --check`. Also build with `--base=/ai-web-experience-collection/`, run `npm run verify:build`, and preview the project path. In a real browser, check home-to-work entry, direct load/refresh, return-to-Collection, all local fonts/media, primary controls, desktop/mobile composition, reduced motion, resize and tab recovery. Record actual results and distinguish untested device classes. Inspect the final diff and include only task files in Git closeout. Deployment/publishing still requires task authorization.

## Validation and deployment

There is no lint or browser-test npm script. `scripts/prepare-data.mjs` and `scripts/prepare-assets.mjs` regenerate original F1 resources and must not run as verification. Do not commit temporary browser drivers, screenshots, caches, ZIPs or `dist/`.

After UI/motion changes, inspect complete frames at 390×844, 768×1024, 1440×900, 1920×1080, 2560×1440 and 3840×2160, plus wide/short VERDANT. Exercise slow/normal/fine/high-frequency wheel, fast down/reverse, arbitrary stops, scene boundaries, disclosures, every control, menus, reduced motion, immediate-load input, resize and tab recovery. Record actual observations; physical touch, iOS and high-refresh hardware require actual devices.
