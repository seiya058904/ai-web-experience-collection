# 概念与材质记录的使用方式

## 六幕参考图

| 参考 | 采用的内容 | 实现时需要独立处理的内容 |
| --- | --- | --- |
| 00 — Prologue | 左上巨型铭文、右下坯体、狭窄冷侧光与大面积暗部。 | 将粗糙度控制为钢的氧化皮和细坑，避免变成岩石；字体使用正式 DOM。 |
| 01 — Furnace | 局部热光与氧化暗岛、炉口和长边的方向关系。 | 热光必须参与场景照明，不能用橙色页面遮罩替代。 |
| 02 — Strike | 巨锤与砧面的尺度、接触前的间隙和有限火星。 | 火星与回弹必须由击打状态产生，不能只复制定帧粒子。 |
| 03 — Quench | 低水面、可读的长边、余雾与冷白反射线。 | 保持实际几何的截面与尖端连续性，独立处理水面与遮挡。 |
| 04 — Reveal | 斜面与棱脊、方向一致的微划痕、长条反射。 | 真实光源与材质共同决定反射，不把图中的明暗直接当成完整材质。 |
| 05 — Relic | 建筑留白、完整轮廓、呼应首屏的斜向姿态。 | 概念末端残留的热橙不应强制保留；收尾以冷钢状态为方向。 |

六图由独立生成调用产生，坯体长度、厚度和尖端存在差异。它们用于定义视觉方向，不是六个可以直接替换的模型。正式器物由同一程序网格及相容的形态属性贯穿。

## 两张正式贴图

生成目标为两张 2048 × 2048 的无场景、无文字、均匀光照表面细节图；实际输出均为 **1254 × 1254**。原始 PNG 保留在 `textures/originals/`，网站采样其同尺寸 WebP 衍生文件。具体 SHA-256、工具 source ID 和来源链见 `texture-metadata.json`，编码参数与误差见 `texture-encoding.json`。

- **forged-steel**：氧化皮、浅坑与细小作业痕，作为原坯表面的细节信号，并用于部分场景表面的 bump。
- **polished-steel**：纵向精细研磨痕，用于抛光阶段的方向性表面变化。图中纹路沿 V，正式 shader 交换采样轴，使它沿器物长轴延伸。

两图是合成细节来源，不是经测量标定的完整 PBR 通道包。它们没有独立法线、实测反照率或实测粗糙度。正式 shader 对采样值进行组合与重映射；不能把锻造图的暗色直接当成正确的低粗糙度。

当前实现将粗糙表面、磨削斜面和薄刃分区控制，使表面细节与主要反射宽度分别可调。较大尺度的热区由程序场决定，锻造图只参与细节调制，不直接决定整件器物的发光区域。原坯 WebP 在场景初始化时加载，抛光 WebP 在首次抵达第 03 幕或后续章节时加载。

精确无缝平铺未得到像素级保证。当前载入设置采用 `MirroredRepeatWrapping`；这属于采样策略，不修改原图。发布 WebP 采用 quality 96、method 6 的有损编码，减少下载量而不改变尺寸与构图；原始 PNG 仍可用于比较。生成图的微小明暗细节需要受控 bump 幅度和实景查看。本记录说明来源及使用限制；材质画面的评价由验收报告记录。
