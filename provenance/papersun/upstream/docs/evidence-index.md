## Source-ZIP curation and privacy normalization

All source, final stills, actual failure images, JSON reports and review history are preserved. No broader still-history curation is applied. To avoid duplicate continuous encodings, `scripts/package-source.py` omits raw JPEGs in a `-frames` folder only if the matching sequence is CAPTURED, its JSON lists exactly those frames, and the matching animated WebP is structurally complete and contains multiple frames. All JSON, animations, standalone stills, incomplete sequences and non-JPEG metadata remain. No working capture is deleted.

`docs/package-manifest.json` enumerates each omitted sequence, every original raw-frame path and byte count, plus the retained animation and metadata. An omitted frame path in original JSON is a capture-origin reference; use its retained animation in the ZIP. The packager rejects symlinks and detects selected-file changes, sorts entries, normalizes timestamps/modes, records per-file SHA-256 excluding the manifest itself, includes current prepared `dist/` and omits stale compiled assets and dependencies/browser binaries.

**Privacy normalization status: COMPLETE for the included evidence.** [The normalization audit](evidence/evidence-path-normalization.json) records 35 changed text files in two batches, with before/after byte counts and SHA-256 hashes. Location categories are `<project>`, `<qa-runtime>`, `<temporary-browser-profile>`, `<primary-runtime>`, `<extracted-candidate-project>` and `<handoff-candidate-output>`. Application code, screenshot pixels, statuses, assertion failures, observed errors, timestamps and measurements are unchanged. Original candidate audit output was kept separately while verification ran; the included report copies use these disclosed placeholders. No private runtime is required to run the distributed app.
