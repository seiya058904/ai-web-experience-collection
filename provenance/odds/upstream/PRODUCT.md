# ODDS

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Delegated in the supplied execution brief: a lightweight, reproducible frontend such as Vite + TypeScript. This implementation uses Vite, TypeScript, native DOM/SVG/Canvas and Lenis. No backend or account is needed.

## Users

Curious adults who enjoy a finely made interactive object. No statistics background is assumed. Desktop and mobile visitors receive all ten chapters.

## Product Purpose

Make a single ball's journey inviting, then reveal how many independent journeys leave a distribution. The visitor can inspect paths, compare samples, change rules, run an experiment and save the actual result.

## Positioning

A tactile probability exhibit with exact, replayable independent Bernoulli samples. The mechanism is an ideal model; animated trajectories are visualizations, not calibrated collision physics.

## Capabilities and Constraints

Ten substantial English-language chapters and nine reversible narrative transitions. Eight separate image-generation tasks. Real local SVG download, seeded replay, undo, preserved prefixes, explicit next-ball append. All result-changing actions require explicit input. Never change samples on scroll or resize. No deployment, publishing, repository push, PR, release or Collection registration is authorized.

## Brand Commitments

ODDS; cream, matte ultramarine and terracotta; refined desktop sculpture; restrained, intelligent, playful English. No gambling cues, coins, rankings, particle spectacle or supposed quantum explanation.

## Evidence on Hand

The supplied complete ODDS execution brief. NIST and Penn State mathematical references, Exploratorium's marble-machine method, official Lenis documentation. AI images are art references, never exact statistical evidence.

## Product Principles

1. Every visible count comes from the actual saved sample.
2. Individual outcomes and theoretical expectations remain distinct.
3. Browsing never commits an experiment.
4. Endings and mobile layouts receive the same functional care as the entrance.

## Accessibility & Inclusion

Semantic English DOM, keyboard-operable native controls, visible focus, text equivalents for all essential diagrams, reduced motion, optional muted-by-default sound, complete fallback when images fail.
