# BERTH｜交付与验收报告

日期：2026-11-09

## 交付结论

BERTH 已制作成可本地运行的英文夜车叙事网页，包含十个章节、九处相邻转场、正式生成图像、两项核心交互，以及源码、依赖锁文件、文档和实际浏览器证据。

**当前状态是“已实现，可运行，部分浏览器验收通过”；尚未达到原任务要求的全部 G5 视觉与跨端验收。** 桌面首屏已经取得完整素材加载后的真实截图，文字交互和资源降级状态下的桌面、手机前进主路径也已经实际操作。高清手机全程、九处转场的五帧矩阵和连续反向观看等仍未验证。

主要阻塞来自共享预览地址：它多次返回其他项目的页面，图片请求也收到错误内容。重新启动预览并使用独立解压的生产构建，曾恢复完整桌面画面；后续响应式切换再次出现资源失败。因此，报告把“源码及资源完整”“功能实际有效”和“完整美术验收”分别记录，不用构建结果替代视觉证据。

## 1. 下载包包含什么

`BERTH-source.zip` 解压后得到 `BERTH/` 目录，其中包括：

- Vite + TypeScript 工程、固定版本依赖与 `package-lock.json`。
- 十章英文正文、语义化标题、原生控件、章节导航和九处由滚动进度求值的转场。
- 正式 WebP 场景、响应式尺寸和轻量恢复预览；运行所需图像均随包提供。
- Cormorant Garamond、DM Sans 的本次使用字体文件副本，以及软件与字体的原始许可、通知和校验记录。
- `Start-BERTH.cmd`、`Preview-BERTH.cmd` 和英文 README。
- Visual Bible、设计 token、人物与物件连续性台账、生成提示词及采用记录、架构说明、独立审查和验收记录。
- 真实浏览器截图、观察数据、单元测试、视口检查页面和三种异常场景检查页的生成脚本。

包内没有 `node_modules`、构建缓存、浏览器资料、密钥、上传辅助脚本或其他项目。它不依赖原始生图目录、临时图像链接、运行时生图服务、账户、数据库或 API Key。首次安装依赖需要 npm 网络连接。

## 2. Windows 运行方法

### 快速启动

1. 安装带 npm 的 **Node.js 24 或更新版本**。
2. 完整解压 ZIP，进入其中的 `BERTH` 文件夹。
3. 双击 `Start-BERTH.cmd`，等待依赖安装结束。
4. 在浏览器打开 `http://127.0.0.1:5173/`。

需要查看生产构建时，双击 `Preview-BERTH.cmd`，再打开 `http://127.0.0.1:4173/`。该脚本会先构建，再启动预览。终端按 `Ctrl+C` 停止服务。

脚本使用带引号的自身目录路径，并检查 Node/npm 和安装、构建结果。5173 或 4173 被占用时会报错，需要先关闭占用相应端口的服务。脚本已做源码检查；本次运行环境是 Linux，**没有在真实 Windows 上执行这两个脚本**。

### 手动运行

在 `BERTH` 目录打开 PowerShell 或终端：

```powershell
npm ci
npm run dev
```

测试和生产构建：

```powershell
npm test
npm run build
npm run preview
```

请通过终端输出的 HTTP 地址访问。直接双击 `index.html` 不能正确运行 JavaScript 模块及本地资源请求。Windows 启动脚本明确使用 `127.0.0.1`；手动命令使用的地址以 Vite 输出为准。

## 3. 内容与设计成果

故事围绕 Shen Ning 和 Ms. Lin 的两种“第一次”展开：第一次去教社区写作课，以及退休后的第一次独自看海。人物不承担说教式导师角色；剧情由让出灯光、分两张小卡、把讲义带上铺、收到留言和整理行李等具体行动推进。

| 章节 | 时刻 | 核心推进 |
| --- | --- | --- |
| 01 | 20:48 | 进入包厢，发现十二页讲义的开场仍空着 |
| 02 | 21:05 | 邻铺让出一点灯光，宁把讲义挪近 |
| 03 | 21:32 | 两个被划掉的开场，局部灯光比较 |
| 04 | 22:17 | 走廊接水、经过小站，听见“不用赶铃” |
| 05 | 23:06 | 退休与看海，两张空白卡分别交给两人 |
| 06 | 00:14 | 林的眼镜和卡留桌，宁带讲义和自己的卡上铺 |
| 07 | 02:10 | 宁半夜醒来，读者选择或写下第一句 |
| 08 | 05:38 | 同一空间渐亮，宁带纸下铺，收到林的留言 |
| 09 | 06:12 | 同一枚回形针从讲义移到两张卡，两人收拾行李 |
| 10 | 06:37 | 林先离开，宁随后；空包厢回应入口，便笺保留当前文字 |

视觉沿用固定的小包厢：右侧上下铺与梯子、远端圆角窗、窗下小桌、左侧通道与挂钩。午夜蓝、灯光蜜黄、米白纸张和灰绿织物形成主色关系，清晨逐渐引入偏冷日光。标题使用文学感衬线，控件使用简洁无衬线，故事时间使用等宽字体。

桌面 Hero、独立竖屏 Hero、夜谈、清晨及空包厢都有对应资产。正式图像不承担可读文案；讲义、划线草稿、两张便笺、用户输入和交互反馈都是真实 DOM 文字。低动态模式保留全部十章与互动结果。

生成记录包含 **32 个成功的独立原始输出，其中 10 个是后来被替换的修正版**；当前定稿涉及 22 个不同图像用途。交付中有 19 个运行时画面条目和 8 张概念审查图，部分概念图与运行画面复用同一定稿。运行资产按全尺寸、小尺寸、恢复预览输出，共计 **65 个 WebP 文件**。这些数字不把缩放副本误计为新一次生图。

原始提示词、实际输出文件名、参考图、修改原因和采用位置见包内 `docs/image-generation.md`、`docs/asset-records.json`。没有编造工具未提供的 seed 或参数。

## 4. 两项核心交互

### 第三章的灯光比较

Reading、Soft、Off 改变该章比较视图的受光和纸面处理，正文持续可读。默认 Soft，选项保存在本地。后续章节按自己的叙事灯态显示；返回第三章才恢复比较选项。离章交接的灯光接管已实现，但所有光档下的正反向中间画面尚未完成完整视觉复验。

### 第七章的第一句

默认句是 `Good morning. I’m Shen Ning.`。读者可以选择另外两个预设，也可以编辑后点击 **Keep this line** 提交。单纯输入草稿不会修改已保存的便笺。

文字最多 120 个 Unicode 码点，截断停在完整字素边界，不拆开家庭 emoji 等组合。非空输入保留原语言、换行及前后空格；全空白提交恢复默认。撤销恢复本次访问中先前提交的内容，Restore 恢复默认。

有效内容进入第八处转场的纸张细节，以及第九、十章的便笺。复制反馈属于当前卡片；复制不可用时有就地手动选择文本的替代实现。**复制成功已实测，拒绝剪贴板的浏览器失败路径尚未实测。**

灯光、已提交句子和动态偏好保存在该浏览器、该站点地址的 `localStorage` 中，不发送给服务器。不同主机名或端口的保存内容互不共享。声音每次加载都从静音开始，用户主动启用后才合成本地车轮声。

桌面、手机的 card-binding 截图分别位于转场局部进度约 0.5003 和 0.4997；纸夹仍在移动中，不是最终夹合端点。两张卡及当前用户文字可读，但最终纸夹接触、文字避让、字幕与动作时机仍需端点及连续观察。

独立复核的总处置仍为 **recapture：剩余画面需要补充采集和审查**，没有全站视觉通过、无障碍通过或全部验收通过的结论。详见 `docs/finish-review.md` 的十项对照。

## 7. 已修复问题与尚未通过的项目

已修复并分别记录证据的问题包括：章节计数把根节点算成第十一章；手机转场进度与 sticky 位置不一致；复制反馈位置不对应当前卡片；输入空格和 emoji 边界；结尾文案重复；移动端失败图重试同一 URL 而悬挂；Hero 失败替代文字压住导航；菜单外部点击抢走焦点。第五处转场重复露出林的姿态问题已通过床沿遮挡及几何修正处理，**最新修正尚未得到浏览器逐帧视觉确认**。

仍未验证的主要范围：

1. 正常资源下完整桌面与手机视觉旅程，以及连续慢速反向、快速跨界滚动。
2. 九处转场各自 0/25/50/75/100% 与临界两侧，特别是第五处遮挡和第八处纸夹最终接触。
3. 高清手机 Hero、夜谈、清晨、结尾，以及其他尺寸的全部复杂画面。
4. 125%/150%/200% 浏览器缩放、系统级降低动态切换、真实手机软键盘、触控和地址栏变化。
5. 受控图片/字体失败、存储拒绝、剪贴板拒绝、慢网络、请求乱序和网络恢复。
6. Windows 实机、实体安卓/iOS、Safari、Firefox、屏幕阅读器、音频听感和长期资源占用。

项目采用 DOM/CSS/SVG，没有 WebGL 渲染器，因此 WebGL 上下文丢失不是本工程适用的检查项。其他项目不能据此豁免。
