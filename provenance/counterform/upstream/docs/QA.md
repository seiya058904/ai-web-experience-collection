## 4. 单份原生文字交接：38 / 38

LIVING → PAGE 不再同时叠加两份不同换行的标题。辅助层使用原生 `Range` 读取两端真实位置，只绘制一组文本片段；原来的语义化 h2 保留布局。所有片段共用同一组真实字体轴，中间通过统一真实字号收拢，为换行迁移留出空间。没有横向拉伸，也没有新增动画时钟。

局部确认覆盖默认短句、自定义文本、组合音标、ZWJ emoji、空输入回退，以及 360px 下 72 个连续 W 与三轴组合极值。检查两端位置、字体设置、字素边界、单份文字、中间边界与布局读取；另外按 0.02 步长检查 51 个进度点的跨词间距，避免把 `type room` 或 `to breathe` 挤成连词。

两端原生 Range 的 x/y 和高度精确对齐；普通词宽差不超过 1/64px。72W 的部分换行子 Range 宽度差不超过 1px，属于连续原生文本与独立片段的边界差异，未使用字形拉伸补偿。缓存后的连续 21 次 `render()` 没有布局读取。

缺少 `Intl.Segmenter` 时使用一份原生段落，不猜测并拆开组合字符。单词中间的空白用于间距约束；同一连续长词因换行形成的片段不会被当成新词插入空格。

## 5. 材质交接与缓存：32 / 32

材质模块定向检查没有运行错误。MARK → PRESS 用一个 renderer 组合两个材质视图；源石板先缩到字模附近，再完成表面交换，避免不同尺寸物件直接堆叠。

| 检查 | 结果 |
| --- | --- |
| 组合端点与原单场景 | MARK、桌面 PRESS、手机 PRESS 的 RGB 每像素相同。 |
| 相邻混合进度 | 0.49 → 0.50 → 0.51，最大通道变化 4 / 255；没有中点切换跳变。 |
| 上下文恢复 | 双材质组合在丢失、恢复后截图字节一致。 |
| 窗口移动缓存 | 1440 × 900 与 390 × 844 各检查 24 个移动、缩放、反向状态；GPU framebuffer 捕捉次数始终为初始的 2 次。 |
| 回到起点 | 两档窗口移动测试的起点与返回截图字节一致。 |

`sourceSize` 固定原相机和捕捉尺寸，移动只改变合成中的位置与大小。PRESS → DIVIDE 则移动现有完整材质画面，使纸面字形接到衬线对照位置。以上是已测资源行为，不是实体设备 FPS 承诺。

## 6. 回退与最终审美

回退集成共 **8 个场景、41 / 41 个断言通过**，覆盖 390 / 1440 两档视口。当前精修版另做阅读模式、无 JavaScript、WebGL 失败、字体加载失败以及退出动效的定向集成冒烟，重点检查新文字层不会留下空白标题或常驻遮挡。故障注入的预期请求失败与正常运行错误分开记录。

本轮独立审美检查先发现相同 R 的双影、旧说明与移动物件相撞，以及最后两章换行造成的双份标题。修正后，复核确认开屏与标注、材质收束、R 的实际落点、ANATOMY → LIVING 清场、七章稳定画面和末章导航成立。最后仅针对提前清字和跨词间距做定点确认，没有追加新设计。
