### 字体确实改变了字形

除检查计算后的 CSS 值，还在浏览器内用固定 100px 字号的 `Rag & reading` 测量了原生文字宽度。每次只改变一条轴，其他轴保持规定的测试值：

| 轴 | 最小值时宽度 | 最大值时宽度 |
| --- | --- | --- |
| wght 100 → 1000 | 490px | 735px |
| wdth 25 → 151 | 387px | 784px |
| opsz 8 → 144 | 688px | 591px |

这些数值是该字体、字符串与本轮浏览器的测试结果，不能作为任意文字的通用比例。它们与随包字体元数据一起确认了实际设计空间的变化；宽度不是 CSS 拉伸。

## 4. 时钟、焦点与字体故障

| 场景 | 结果 |
| --- | --- |
| 空闲后滚轮 | 空闲两秒期间 RAF 调用计数保持 2 → 2；唤醒首帧逻辑时间差为 0ms，随后约 16.7ms；滚动经过 0 → 25 → 47 → 67 → 85px 等中间位置。 |
| 滚动停止 | 动画结束后再观察半秒，RAF 调用计数保持 53 → 53。 |
| 空闲后章节跳转 | 首帧逻辑时间差为 0ms，跳转持续插值，没有消耗整个空闲时长。 |
| 隐藏／恢复处理器 | 模拟隐藏 1.3 秒期间帧数保持 28 → 28，恢复首帧逻辑差为 0ms。这里使用合成的可见性事件，未宣称验证原生操作系统挂起。 |
| 减少动态效果下的导航 | 阅读模式，以及系统减少动态效果但用户手动开启 Motion 的组合，都能把键盘焦点留在目标标题。 |
| 字体请求失败 | 阻断 Roboto Flex 后，三个轴禁用，回退身份与提示可见，终章不宣称轴已应用；文字编辑和 Reset 保持有效。 |
| 慢字体与迟到恢复 | 延迟响应 9.5 秒，8 秒时显示等待状态；输入文字保留，真正加载成功后解除禁用，键盘增量真实改变计算后的字体重量。 |

字体故障注入产生预期的网络请求失败；正常、延迟后成功、焦点和时钟场景没有 JavaScript 或控制台错误。

## 6. 两轮审美与最终修正

第一轮独立审美检查发现了手机 SPACE 标注越界、平板 R 与副标题碰撞，以及隐藏换行产生的词句粘连。修正后进行了第二轮独立检查，结论为：**正常模式可以交付，没有剩余的重要视觉问题**。

第二轮覆盖桌面／手机／平板联系表、原尺寸修正位置、桌面与手机全部四个印刷阶段，以及代表性的章节中间和进入帧。评审确认字腔持续可辨认，稳定构图与过渡各自有清楚节奏，手机功能小字增大后没有引入碰撞。

机械检查另外发现矿物色背景的正文对比度与功能小字尺寸问题。现行 `#7a8d95` 对 `#20211e` 的计算对比度约 **4.68:1**，功能小字设为至少 11px。纸色、真实字体选择、章节大写编号、巨型字形裁切和紧凑展示字号保留为用户明确要求的设计语言；这些选择没有用于放宽正文或控件的裁切要求。

桌面静态印刷回退与恢复后的材质属于单独故障检查，已修正并复测；最终实际截图也进行了人工查看。概念参考与实现差异见 [FIDELITY.md](FIDELITY.md)。
