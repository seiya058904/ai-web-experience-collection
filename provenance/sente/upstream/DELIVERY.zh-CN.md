# SENTE｜交付说明与验收结果

交付日期：2026 年 11 月 9 日。

## 1. 交付结论

已制作 SENTE 的可运行版本：全英文的十章围棋互动叙事、九处可逆的章节交接、三道真实落子的 7×7 棋题、双眼与单劫示例，以及保留实际尝试的本地观察笔记。源码、预构建网页、正式图片与字体、九张真实生图原稿、生成记录、测试与浏览器证据一并交付。

规则、交互和工程复现已有实测证据。**这不等于原始创作与验收契约逐项全部通过。** 当前采用二维木台环境、精确 SVG 棋盘与克制的编辑式转场；完整灯光／镜头揭示、部分空间接替和结尾的宽空盘收束仍有简化。浏览器实际下载 SVG 到磁盘、原生页面缩放及若干真实设备条件也未获得验证。下面分别说明实现、证据和限制。

本次未部署、发布、推送、创建 PR／Release，也未加入现有合集。

## 2. 在 Windows 上运行

### 直接观看附带的成品

1. 安装或确认已有 **Node.js 24**。
2. 完整解压 `SENTE-source.zip`，进入其中的 `SENTE` 文件夹。
3. 双击 `START-SENTE.cmd`，保持命令窗口开启。
4. 在浏览器打开窗口显示的地址，默认是 `http://127.0.0.1:4173/`。
5. 回到命令窗口按 `Ctrl+C` 停止服务。

附带的 `dist/` 已经构建好；运行它无需下载 npm 包，也不需要账户、API Key、数据库或付费运行服务。页面通过本地 HTTP 服务运行，请不要直接双击 `dist/index.html`。

也可以在项目目录中执行：

```powershell
npm start
```

或者直接使用 Node：

```powershell
node scripts/serve.mjs
```

端口被占用时：

```powershell
node scripts/serve.mjs --port 4174
```

另附 `START-SENTE.ps1`。它不会修改 PowerShell 执行策略；若被本机策略阻止，使用 `.cmd` 或上述 Node 命令即可。**Windows 启动器已提供，但未在真实 Windows 环境执行。** 本次安装、构建、服务与浏览器检查运行于 Linux 环境，不能据此声称 Windows 实机测试通过。

### 修改源码与重新构建

安装依赖需要访问 npm 软件源：

```powershell
npm ci
npm run dev -- --host 127.0.0.1
```

检查、测试、构建：

```powershell
npm test
npm run check
npm run build
npm start
```

锁定的主要版本为 Vite 8.3.6、TypeScript 7.0.2、Lenis 1.3.27。实际验证环境为 Node 24.22.1、npm 11.9.0。依赖图由 `package-lock.json` 固定。

## 3. 已实现的内容

| 章节 | 实际内容与操作 |
| --- | --- |
| 01 · Before a move | 在空盘任意交叉点试落一颗黑子、查看气、收起棋子；与三题记录互相独立。 |
| 02 · Room to breathe | 继承首颗黑子，或明确使用默认 D4；比较中央、边与角的 4／3／2 口气。 |
| 03 · Connected, not just close | 检查 D3、D4、E4 的同一棋串与去重后的 7 口气；F5 斜向相邻但不连接。 |
| 04 · The last liberty | P1 实际落子、拒绝占位、保留合法错误尝试、提子、撤回与复位。 |
| 05 · Two quiet spaces | 在给定双眼结构的 C3、E3 尝试白子，均按无气规则拒绝并保持原盘。 |
| 06 · A small bridge | P2 联络两串；成功后显示五颗连通黑子与八个不同的气点。 |
| 07 · The next move matters | A／B 从共同起点分别回放，保留独立棋子与步骤；手机同时保留两条步骤列表。 |
| 08 · Letting one go | P3 包含明确的白方教学回应，支持自动或手动下一手、逐步撤回与两种结果对照。 |
| 09 · Not the same again | K1 单劫示例比较完整局面，拒绝立即回提造成的重复。 |
| 10 · Leave with a little more | 展示三题真实尝试与实际看过的局面；未玩题目标作 Example；生成独立 SVG 观察短笺。 |

滚动只改变叙事浏览位置，落子只由明确操作提交。回到前章、跳章或复位题面不会把历史改写成“一次答对”。P3 若只看过黑方一步，记录不会提前假装已经看到白方回应。

棋盘支持鼠标点选、方向键移动、Enter／Space 确认以及坐标下拉选择。箭头在真实盘边停止，不跨行绕回。手机 P1／P2 的结果和撤回入口置于棋盘下方；桌面保留侧栏阅读结构。声音默认关闭、由本地合成，不承担唯一的规则反馈。

规则引擎先处理对方无气棋串，再判断己方无气和即时重复。这里实现的是有限教学局面与 **simple ko（单劫）**，没有完整整盘计分、贴目、超级劫、联网对弈或围棋 AI。P3 的白方回应是公开的固定教学脚本，其目标不代表任何对局中“救两子都比提一子好”。

## 4. 设计与素材

先完成了九张可独立查看的实际生图成果：三种不同 Hero 构图、桌面精修、独立竖屏构图、双眼重点、取舍对照、交接中帧，以及额外木纹材质。原稿、真实提示词、工具记录、用途和选用理由保存在 `art/`。

正式网页使用两张优化后的 WebP：桌面木台环境与棋盘木材。全部规则网格、坐标、棋子、气、连通关系和按钮由精确 SVG／DOM 绘制，不把 AI 图片里的棋谱、伪坐标或文字当作规则数据。

页面以温木色、炭灰、纸色和克制的朱红组成；标题使用 Bodoni Moda，正文使用 Manrope。字体在本地提供，授权文本随包附带。手机采用上盘下文的独立流式构图；超宽屏将完整 Hero 控制在 2200px 宽的木台画面中，以纸色留边消除木纹拼接硬边。

八个实际运行文件总计 **346,913 字节**，包括 HTML、脚本、样式、两个 WebP、两个 WOFF2 和 favicon。九张大幅 PNG 原稿只用于交付检查与后续编辑，网页不会一次下载这些概念图。

详细设计约定见 `DESIGN.md`、`.impeccable/design.json` 和 `art/ART-DIRECTION.md`。

## 5. 规则与工程测试

**61 项 Node 测试全部通过，无失败或跳过。** 覆盖规则、历史记录和 SVG 生成；其中 SVG 模块有 10 项测试。另有独立 Python 实现，对三题全部空点首着进行枚举。

| 棋题 | 已枚举合法首着 | 唯一满足目标的首着 | 已核对的关键结果 |
| --- | ---: | --- | --- |
| P1 | 45 | D5 | 提走白 D4，D4 确实变为空点。 |
| P2 | 41 | D3 | 五颗黑子为同一串，不提子，共有八口气。 |
| P3 | 38 | C5 | 经过白 F6 后，C3、C4 仍在盘上。 |

P3 的全部 38 种规定回应均合法。F6 路线会先提走白 F5，再由白 C5 提走黑 C3、C4；C5 路线保住标记棋串。双眼拒绝、自杀判定、斜向不连接、去重共享气、分支撤回与完整局面重复均有相应检查。

独立源码候选包实际解压后执行了 `npm ci`、`npm test` 和 `npm run build`，全部退出码为 0。重新构建前后的八个 `dist/` 文件逐字节相同；五十个非构建文件未改变。预构建版本在安装依赖前即可通过附带服务器运行。预置／重建版本在根路径与 `/subpath/` 的服务共通过 **54 项 HTTP 断言**，包括内容哈希、MIME、HEAD、缺失资源 404 和路径边界。

随后在实际浏览器打开独立重建的运行文件，以坐标控件再次完成 P1 D5、P2 D3、P3 C5→白 F6。此次 390×844 CSS 视口内十章和九处交接均在，横向溢出为 0，棋盘与按钮中心最大差为 0.019px，六项记录到的运行资源均返回 200，观察窗口内无运行错误事件。

最终完整 ZIP 的校验值见配套 `SENTE-SHA256.txt`；完整文件清单及包内哈希见 `MANIFEST.sha256`。测试日志与独立复现记录在 `docs/evidence/`。代码候选包的中间校验值不能当作最终交付 ZIP 的校验值。

## 6. 浏览器与视觉证据

测试浏览器报告为 Chromium 156、Linux x86_64、DPR 1。使用同源 iframe 设置精确、未进行 CSS 缩放的视口；这不等于真实手机或真实 4K 硬件。

| 检查范围 | 实际结果 |
| --- | --- |
| 320×700、360×640、390×844、768×1024 | 均未测到横向溢出。 |
| 1440×900、1920×1080、2560×1440、3840×2160 | 均未测到横向溢出。 |
| 844×390 短横屏、999×800 与 1000×800 断点两侧 | 均未测到横向溢出。 |
| 棋盘几何 | 七个可交互棋盘各有 49 个交叉点按钮和一个活动 Tab 停靠点；整个矩阵的最大中心差为 0.022px。 |
| 主交互路径 | 1440×900 与 390×844 实走规则、错误尝试、撤回、分支、P3 自动／手动回应、导航与刷新恢复。 |
| 低动态 | 手动低动态模式仍保留十章与交互；P1 键盘操作完成，恢复完整动态后已有记录不丢失。 |
| 资源失败 | 两张图片与两份字体真实返回 404 时，三题仍可完成；正文回退字体、棋盘底色与精确 SVG 保留。 |

最终转场证据来自同一正式构建、同一组答题记录：九个边界各取 0／25／50／75／100% 五帧，共 **45 张真实浏览器截图**。九次反向中点检查的进度与说明文字均与正向一致。取样前后的完整笔记文本和 196 个 Hero／三题交叉点描述完全一致；答题记录数保持为 8／5／5。

`docs/evidence/transitions-contact.jpg` 是全 45 帧的联系表；原始 1440×900 图片逐张保留，并有尺寸和 SHA-256 索引。局部进度 0% 或 100% 时，边界可能刚在视口外，因此相应图片证明的是边界与相邻构图，不是宣称每张都完整显示转场板块。静帧和反向中点检查也不能代替连续帧率或所有快慢滚动测试。

早期长驻预览中出现过异常材质截图，并有不同答题状态的混合取样；这些不能作为最终材料证据。重新加载、检查独立资源路径并固定同一会话状态后，重新取得全部 45 帧。最终联系表只使用后一次取样，不通过修图掩盖旧帧的问题。

## 7. 性能记录的解释

一次未由测试工具施加网络／CPU 节流的本地生产加载，在 390×844 CSS 视口记录到：FCP 180ms、应用交互就绪标记 109.1ms、Hero 图片解码与字体等待完成标记 158.4ms。

这是单次本地观察。没有独立控制冷缓存或环境外部节流；应用标记也不等于输入延迟测量或完整艺术镜头播放完成。因此不据此承诺真实设备加载时长、60FPS、Lighthouse 得分或长期内存稳定。

## 8. 明确未完成或未验证的部分

### 视觉实现与原始创作要求的差异

- Hero 已有空盘、试落、查看气、收起、继承与返回；完整的灯光／相机揭示和透视接替没有按原始六状态逐镜头实现。
- 九处边界采用独立、清楚、不透明的棋盘快照与小幅运动、五段说明文字；未完整实现全部指定的空间物体接替。
- 提子由规则立即提交，随后短距离抬升淡出；没有完整移向盘外或入碗的路径。
- 第二章低动态模式通过选择器访问中央／边／角示例，没有同时并列三个盘面。
- 结尾使用观察谱、装饰黑子与回到开头的链接，没有实现更宽空棋盘上的同一颗 Hero 棋子收束。

### 环境与端到端验证限制

- **SVG 下载到磁盘：未验证。** 实际点击后生成 Blob、出现保存与预览入口，并打开标题为 “SENTE — Three observations” 的预览标签。远程下载事件等待超时，工具也因安全策略拒绝读取 `blob:` 标签。未绕过该限制，不能把生成器测试冒充成功下载与已保存文件的视觉验收。
- 原生浏览器 125%／150%／200% 缩放未验证；CSS 视口模拟不能替代。
- 真实 Windows、Android／触摸设备、真实 4K 显示器、其他浏览器内核未验证。
- 实际屏幕阅读器、操作系统级低动态偏好切换、可听声音输出未验证。
- 完整慢网络／乱序资源矩阵、CPU 节流、连续 FPS、长期内存／监听增长、后台恢复和所有历史返回手势组合未验证。
- 手机 P2 的早期截图可确认结果与 Undo 的相邻位置，但该图含异常纹理，未作为最终材质证据交付。最新重建版本的手机 P2 操作与资源成功有记录；最终金色木盘的 P2 转场截图来自桌面视口，二者不混称。

这些限制已保留在 `docs/QA-REPORT.md` 和 `docs/progress.md`，本报告不使用“全验收通过”表述。
